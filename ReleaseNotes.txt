Version 2.0.0-rc8      13th November 2025
==================================================
This release candidate includes important fixes and improvements across
navigation, BVH accuracy and consistency, CUDA RDC handling, compiler
compatibility, and general code robustness. It also removes deprecated or
broken components and improves documentation.

- Navigation and geometry fixes
  - Fixed a long-standing bug in `LocatePointIn` in both `BVHNavigator` and
    `LooperNavigator`. The function received points in the *parent* reference
    frame of a volume, but the BVH expected points in the *local* frame.
    The missing transformation caused incorrect navigation for all but the
    world volume. The behavior is now corrected and documented.
  - Updated `RelocatePoint` to match the corrected `LocatePointIn` behavior.
  - Added a new `LocatePointInNavState` method, which takes a point expressed in
    the local coordinate system of an existing navigation state and finds the
    deepest state containing that point.
  - Matched polycone phi-angle readjustment to Geant4 (and UPolycone wrapper),
    resolving inconsistencies observed in the CMS D110 Run4 geometry.

- BVH improvements and cleanup
  - Unification of BVH and BVHSurf: removed the diverged `BVHSurf` and merged
    all functionality into the main BVH implementation. Removed also
    `AABBSurf` and `BVHNavigatorV`, transferring remaining useful functions
    into BVH.
  - Increased error tolerance for `ComputeIntersectionInvDir` from 10 to
    500 ULP to avoid false hits inside approached AABBs.
  - Restored solids’ version of `ComputeSafety`.
  - Made internal `ComputeSafety` precision use `Real_t`, avoiding
    unnecessary casts and enabling precision-templated BVH variants.
  - Relaxed and simplified several internal checks.

- CUDA and build-system updates
  - Removed broken CUDA RNG implementation.
  - Major updates to CUDA RDC handling in `CudaRdcUtils`:
      - Avoid propagation of `-Wl,--no-undefined` when building CUDA RDC
        intermediate libraries, which by design contain undefined symbols.
      - Explicitly allow undefined symbols via platform-appropriate options
        (`allow-shlib-undefined`, `-z undefs`) where available.
      - Added missing `cudart` linkage for non-CUDA libraries depending on
        CUDA libraries.
      - Updated CudaRdcUtils to version 13.
      - Removed dead code, debug remnants, and global linker flag restoration.
  - Fixed build errors with Clang 19 and CUDA 12.9:
      - Corrected device annotations and visibility attributes.
      - Fixed use of nonexistent device functions.
      - Added a warning when host compiler and CUDA compiler differ.
      - Fixed an issue where VecCore’s `check_language(CUDA)` erased
        `CMAKE_CUDA_HOST_COMPILER`. A wrapper for `find_package(VecCore)`
        now prints VecCore version and components at configure time.
      - Updated `.gitignore` to allow storing CMake preset files in the
        source directory.

- Compiler warnings and portability
  - Fixed two macOS warnings: an uninitialized BVH constructor variable and
    removal of an unused branch intended for surface BVH construction.
  - Enabled compiler flags properly: previous CMake logic referenced variables
    that were not set. Compiler flags are now selected using
    `CMAKE_CXX_COMPILER_ID`. Also fixed new warnings in `testRaytracing.cpp`.
  - Fixed `-Wreorder` warning by correcting the initialization order of
    `BVH::fDepth`.
  - Added portable pragma unrolling via `VECGEOM_PRAGMA_UNROLL(N)`, enabling
    consistent loop unrolling and removing warnings in the generic trapezoid.
  - Fixed warnings for gcc15.

- API and type namespace updates
  - Moved `Precision`, `NavIndex_t`, and `uint_t` out of the global namespace
    into `vecgeom`/`vgbrep`. This change improves namespace hygiene and
    consistency.
  - Added `VECGEOM_PRECISION_NAMESPACE` macro to preserve compatibility with
    previous dev and v1.x releases.
  - Updated CUDA paths and dependent code accordingly.

- Miscellaneous
  - Fixed minor annotation issues and improved documentation in several areas.

Version 2.0.0-rc4        27th May 2025
======================================
Surface model:
- The 'frames' surface model (framework for accelerated modeling of
  embedded surfaces) was introduced. It provides a GPU-friendly
  implementation of Geant-like hierarchical 3D solid modeling based
  on bounded half-spaces. The model can be constructed transparently
  on the host based on an in-memory VecGeom solid model and deployed
  to the GPU via simple API.
- 'frames' provides header-only stateless navigation API on the GPU,
  similar to the interfaces used for navigating within the VecGeom
  solid model.
- The model supports a set of primitive half-space types, such as planar,
  cylindrical or conical, and a set of frame types to create bounded
  regions   on the half-space surfaces, such as window or ring. Introduces
  FramedSurface objects that store the intersection of solids with
  surfaces, enabling efficient navigation and reducing computational
  complexity.
- GPU-Friendly Design: Eliminates recursive calls and virtual functions,
  reducing register and stack usage, and enhancing occupancy on GPUs.
  This design addresses divergence issues inherent in the solid model.
- Mixed-Precision Support: Supports both double and mixed-precision
  computations, allowing for flexibility in balancing accuracy and
  performance based on simulation requirements.
- Utilizes BVH acceleration structures to expedite collision detection
  and ray tracing, achieving significant speedups.
- Demonstrates controlled memory footprints and conversion times across
  various detector geometries, ensuring scalability for complex
  simulations.
- Replaced the GPU solids hierarchy with an indexed LogicId/PlacedId
  schema for better performance and memory usage (surface model w/o solids)
- Ongoing Development: While already merged into the master branch, the
  surface model continues to evolve, with efforts focused on expanding
  support for additional solid types and further optimizing performance.

Portability macros
- New GPU portability macros added, used for setting up GPU and exception
  handling.
- VECGEOM_DEVICE_API_CALL portability macro (CUDA/HIP, only CUDA in use 
  for now) for calling and checking API functions.
- VECGEOM_DEVICE_API_SYMBOL to have portable symbols
- VECGEOM_ASSERT 
- VECGEOM_VALIDATE for always-on runtime error checking and throwing
  std::runtime_error if it fails

Shapes
- Contains: improved Contains() functions for all shapes to correctly
  handle points on surfaces and eliminate boundary artifacts.
- Generic Polycone: fixed construction logic to ensure valid geometry in
  all configurations.
- Polygon & Box: added a small tolerance in edge and face tests to prevent
  crashes during geometry relocation.
- Sphere: corrected the DistanceToIn() implementation for robust ray
  entry calculations.
- Polyhedron: introduced a well‐behaved Z‐plane index finder and repaired
  several issues in PolyhedronStruct.
- Tube: fixed a typo in the Y‐component of the normal vector for
  phi‐plane intersections.
- Boolean Solids: properly compensate internal pushes in subtraction
  operations to restore correct shape boundaries.
- Buffer-based allocation for all containers (Vector, SOA3D, AOS3D) and
  for several data structures (Quadrilaterals, Planes). Allocation-free
  creation of polycones and polyhedra on GPU based on this feature.
- UnplacedVolume::Normal became a usable interface

Navigation
- Enhanced global navigation robustness, including stability fixes for
  grazing rays for most solids. Added ShapeTester test for grazing rays.
- Fixed NavStatePath::GetLastExited to guard against out-of-range indices.
- Resolved invalid reference checks in TestBVHNavigator to prevent
  intermittent crashes.

Configuration
- Refactored CMake options and definitions; fixed the version‐string logic
  and added automatic versioning based on the current Git branch.
- Ensured the final VecGeom library is retained when using “as‐needed”
  linker flags.
- Updated CI Docker image location and expanded tested configurations for
  consistency across platforms.
- Corrected build failures under CUDA 11.5 with VecCore 0.8.2; addressed
  -Wmissing-template-arg-list-after-template-kw in Clang 19, linker/Clang 16
  warnings, and various GCC 14 diagnostics.

CUDA & GPU
- Integrated CudaRdcUtils v12: synchronized with upstream
  CudaRdcUtils.cmake, migrated VecGeom into a VecGeomCUDA project, and
  forward-ported RDC settings and libraries.
- Propagated CUDA include paths to the host compiler for seamless builds.
- Enabled single-precision support in the solid BVH; updated CudaManager
  to accept a null “world” pointer on the device.
- Switched device code to use VecCore math routines instead of std for
  consistency and performance

Logging & Diagnostics
- Adopted the unified logger for important messages in core modules and
  VGDML; updated documentation accordingly.
- Reduced spurious “calling host from host/device” warnings and refined
  middleware log levels for cleaner diagnostics.

Memory Safety
- Prevented reads of destructed memory (closed VECGEOM-624) by strengthening

- Fixed several uninitialized constructors to eliminate undefined behavior.

Device API
- BVH Manager: added device‐pointer access APIs and introduced the
  VECGEOM_BVHMANAGER_DEVICE feature macro for downstream consumers.
- Defined a set of device‐portable API calls and assertion macros to ensure
  consistent behavior across CPU and GPU builds.

Persistency & VGDML
- VGDML conversion now uses a map lookup instead of linear search for
  registered volumes, greatly improving conversion performance.

Miscellaneous

streamline the public API.

- Fixed compilation warnings on macOS and resolved errors under GCC 15.

Navigation:
- In VNavigator, simplified the logic which uses the mother volume convexity to
  prioritize daughter checks. This approach is not always justified because
  it may increase the search range for daughter candidates. The current
  approach is conservative and uses the distance to mother first to limit
  the search distance for daughters, only if there are daughters. The check
  for daughters at this point spares extra checks in the derived navigators,
  which in the case of BVH was even generating a crash.

Persistency:
- Added vgdml support for UnplacedEllipticalTube, UnplacedEllipticalCone
  and UnplacedEllispoid shapes.
- Fixed reading of (simple) extruded solid.

Shapes:
- Updated Polycone/Cone implementation to only use kConeTolerance.
  Fixing cases of stuck tracks in ATLAS simulation.
- [VECGEOM-542]: In Tube::DistanceToOut(), added logic to detect point location
  in Phi sector of a tube. Now SafetyToOut() uses Wedge to calculate the
  SafetyToOut() for a point from the phi section.
  These modifications fix the mismatches reported by ShapeTester.
  Since now checking the existence of a point in Phi section in DistanceToOut(),
  a minor performance penalty is expected.
- [VECGEOM-602] Fix in Polycone::SafetyToIn() to remove unececessary
  calculations, when a point is outside the Z range.
- Rewritten PolyhedronStruct::Initialize() without use of dynamic memory.
  CUDA has only a very limited amount of scratch space for malloc / new.
  Having many polyhedra in a geometry setup may exhaust that space.

GPU:
- Expose function to change heap limit in CUDA.
  As of now, all "dynamically sized" shapes such as polyhedra, polycones,
  and extruded solids allocate memory in kernels. This is problematic as
  CUDA only has a very limited amount of scratch space for malloc / new.
